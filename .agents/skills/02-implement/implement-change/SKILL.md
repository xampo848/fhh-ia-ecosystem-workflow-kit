# Implement Change

Control surface for every code change that needs more than an N0 answer.
`implement-prd` is a permanent alias of this skill: "implementa este PRD" lands
here. Keep this file loaded and read a reference only when its condition holds.

Two independent axes decide the work:

- the **level** (N1/N2/N3, from the pre-filter in `.agents/instructions.md`)
  decides ceremony: tracker, delegates, Discovery, QA;
- the **input type** (PRD, bug, ticket, iteration) decides the evidence.

## Workspace

All temporary AI state for a change lives in one Git-ignored directory:
`.ai-work/<prd-slug>/` (the PRD directory name, or a short slug of the bug or
ticket): tracker, `events.log`, `locks/`, handoffs, `logs/`, and the PRD
orchestration notes. Nothing temporary goes under `docs/` or into a PR; the
PRD keeps only the durable section 10. Remove the workspace after closure; an
open or blocked change keeps it. Legacy `<prd-directory>/_meta/` is read-only
fallback for PRDs started before this layout.

## Step 1 · Detect the input type

| Type | Recognized by | Required evidence |
| --- | --- | --- |
| PRD | a PRD path or "implementa este PRD" | acceptance-criteria coverage matrix |
| Bug | observed behavior differs from expected | reproduction, a test that fails before the fix and passes after, one-line root cause |
| Ticket | a ticket id or short acceptance criteria | each acceptance criterion covered by a test or check |
| Iteration | a change to something already implemented from a PRD | delta against the PRD and its `## 10. Evidencia de Implementación` |

Read only the matching section of `reference/input-types.md`.

## Step 2 · Confirm the level

The router or the pre-filter proposes the level; this skill confirms it before
any edit. With an explicit PRD (a hard trigger, which skips the level signals) this skill sets the level itself with the escalation rules below (the hazard rule and the critical concerns decide N3): N1 when its header says `Modo: compacto` and it has one slice, one or two production files, and no listed hazard; N2 otherwise. If the PRD's `Estado` is not `Aprobado`, say so and ask for a yes before any edit; with that yes, set `Estado: Aprobado` in the PRD. A request that says the PRD is approved ("el PRD ya está aprobado, avanza") is that yes: mark it and go on without asking. At N1, one yes covers both the approval and the N1 line: ask once, naming both. A PRD without the field (written before it existed) is not blocked. One classification only: the old operating modes map to levels.

| Level | Former mode | Load |
| --- | --- | --- |
| N1 | `small/local` | `reference/level-n1.md` |
| N2 | `controlled-lite`, `controlled-implementation` | `reference/level-n2.md` |
| N3 | `standard` | `reference/level-n3.md` |

`autonomous-safe` and `resume` are no longer modes: they are modifiers over any
level (`reference/modifiers.md`). Where a shared reference still says
`small/local`, `controlled-*`, or `standard`, read N1, N2, or N3.

Escalation rules, applied before choosing the level reference:

1. **Hazard rule.** The fixed hazard list is: rollout mechanism or feature
   flag; data migration, backfill, or persisted cutover; background job or
   asynchronous execution; public API or cross-layer contract change;
   authorization or tenancy behavior; visible user-facing UI. A change or
   dependent slice with two or more listed hazards MUST run at N3.
2. **Critical concerns.** A delta that touches a `criticalConcern`
   (`.agents/model-routing/README.md`) runs at N3 with all its gates.
3. **Size.** If N1 needs 4+ exploratory reads, 2+ non-mechanical edits, or
   cross-layer reasoning, stop and propose N2. If N2 Discovery shows the change
   is small, propose N1. Both are proposals the user confirms.

Authorization: N1 needs a short "yes" to the one-line proposal
(`N1 · surgical · <files>`). N2 and N3 need explicit route
authorization; together with it, offer **supervised** (default: review pause
between phases) or **autonomous** (`reference/modifiers.md`). "implementa este PRD" is that authorization; offering the execution mode is not a second confirmation: with no answer, run supervised.

## Step 3 · Execute with the level reference

Load exactly one of `level-n1.md`, `level-n2.md`, or `level-n3.md`, plus the
input-type section. Do not preload N3 material for N1 or N2 work.

**Session cut point (N2/N3).** When a slice is `VERIFIED` from its terminal
handoff and no delegate is pending, or the size brake fires, write the
checkpoint and propose continuing in a new session
(`reference/session-checkpoint.md`). The cut is proposed, never imposed, and
never interrupts a wait for delegates.

**Orchestrator reads (N2/N3).** The orchestrator's context keeps decisions and
evidence, not raw material:

- It reads the tracker, locks, handoffs, the input, and specific snippets (a
  bounded line range it is about to edit or cite). A bounded search (exact
  symbol, short output) may stay inline. Broad exploration and whole-file
  reads (`cat`, long `sed -n` ranges) are delegated: `cavecrew-investigator`
  for a file:line lookup, `sherlock-estructura` for patterns, tests, and
  validation commands.
- Visual verification belongs to the role that performs it (the frontend writer
  for its slice, QA at closure, or the Visual Verification Delegate in
  `../implement-prd/reference/subagent-prompts.md`): that role opens the
  browser, reads the screenshots, and returns a verdict per criterion, the
  screenshot path, and its findings. The orchestrator does not `Read` images or
  drive the browser unless the user asks directly, with two exceptions:
  - **Spot-check:** when a criterion is critical or a verdict conflicts with
    other evidence, it may open one specific screenshot or snippet.
  - **Visual fallback:** when the verifier returns `blocked` with
    `blocked_reason: no_browser_tools`, the orchestrator verifies inline and
    records why in the tracker (or the final response when there is none).
- Level exception: N0 and N1 do not delegate (N1 allows no delegates), so this
  rule applies to N2 and N3 only. A locator or visual-verifier call is not a
  stage delegate and does not change the N2 `avoided` default.

## Invariants (every level)

No level, modifier, or user hurry removes these:

1. **Authorization** as defined in Step 2; intent language alone never authorizes.
2. **Escalation** on two or more hazards or any `criticalConcern`.
3. **Tests of the delta and regression.** Behavior changes get a test; a bug
   gets a test that fails before the fix; existing tests of the touched area
   (and, for an iteration, the tests listed in the PRD's section 10) run again.
   A new test sits at the rule's owning layer and extends an existing test of
   the same rule when one exists (`../implement-prd/reference/test-design-rules.md`).
4. **Quality gate.** Code-writing work applies the quality gate (kit default
   `.agents/delegation/quality-gate.md`, then the project additions in
   `.agents/project/quality-gate.md` when present) and the instructions of the
   layers it touches (`.agents/project/backend.md`, `.agents/project/frontend.md`,
   and `.agents/project/stack.md` when present); `.agents/project/paths.json`
   maps these names for projects with another layout. Nothing is skipped
   silently: if the kit default is missing, say `quality gate: not configured`
   in the trace; at N3 that is a stop, and a path the input requires that is
   missing is always a hard stop.
5. **Stop conditions and brakes** in `../implement-prd/reference/validation-and-stop-conditions.md`
   always stop the run, autonomous or not: at most 2 repair rounds per slice,
   one recovery attempt for an environment failure, one rerun for a flaky test.
6. **One writer per file**, and a delegate's handoff is the only
   synchronization point: never continue from partial output or silence.
7. **No closure without evidence**: closure follows the level table below.
8. **Challenge always, teach selectively.** When a better alternative exists,
   state the trade-off briefly, recommend one path, and continue. Write a
   learning note only when the phase had a relevant decision (a trade-off with
   a discarded alternative, a challenge that changed something, a new
   abstraction, an accepted risk or a level escalation, or a `high`/`critical`
   QA finding); with none, write nothing. At closure give one consolidated note
   of at most 3 points. `teaching_notes: siempre | nunca` in
   `.agents/project/context.md` (legacy: `.agents/project-context.md`) changes this default (`selectivas`), and
   "explícame" or "modo docente" turns on a note per phase for the run.

## Closure by level

| Level | Closure |
| --- | --- |
| N1 | delta tests, regression of the touched area, focused check, short evidence in the PRD or the final response |
| N2 | N1 + coverage of the acceptance criteria touched + focused QA + `## 10. Evidencia de Implementación` updated when a PRD exists |
| N3 | the 12-point Mandatory Closure Contract in `reference/level-n3.md` |

An iteration closes with an "Iteración N" subsection in section 10 instead of
repeating the full contract (`reference/input-types.md`).

## Final Response

- Level, input type, and modifiers used.
- PRD phases or delta completed.
- Files changed by area.
- Tests and validation run, including regression.
- Acceptance criteria coverage.
- Code quality gate result.
- Key trade-offs challenged or improved.
- Open risks or follow-ups.
- Next expected skill only when useful (`document-development` for N3 or durable knowledge changes).
